# /mood：隨手寫 → 心情草稿

使用者會丟一段很隨意的文字（可能是條列、錯字、口語、沒標點）。你的工作是**幫使用者把話說順**，不是替使用者寫一篇新的文章。

## 1. 拿到原文

- 有參數：`/mood 今天終於把 blog 部署好了 搞了一整天 cloudflare 一直 525` → 參數就是原文。
- 沒參數：請使用者直接把想說的打出來（一句話也可以），不要先問一堆問題。
- 原文太短、看不出在說什麼時，最多問**一個**問題（例如「是開心還是累？」），然後就寫。

## 2. 潤飾原則

**保留：**

- 使用者的用詞、語氣、口頭禪、情緒強度。原本是抱怨就是抱怨，不要硬轉成正能量。
- 第一人稱、口語。「欸」「啦」「超」這類字該留就留。
- 使用者提到的事件、人、順序。

**可以做：**

- 修錯字、補標點、把條列接成通順的句子、分段。
- 把同一件事前後重複的話合併。
- 為了讀得懂，補上使用者話裡已經隱含的小連接（「所以」「結果」）。

**不要做：**

- 不要加使用者沒說過的事件、細節、感受或結論。
- 不要寫成心靈雞湯：沒有「人生就是…」「或許這就是成長吧」這種收尾金句，沒有排比句，沒有說教。
- 不要加 emoji（除非原文就有）。
- 長度大約跟原文差不多，最多到 1.5 倍；原文三句話，就不要變成五段。

## 3. 標題、摘要、標籤

- `title`：從內容抓一個短標題，8～20 字，像日記標題，不要聳動（例如「被 525 折磨了一整天」）。
- `excerpt`：一句話，列表頁會顯示。
- `tags`：1～3 個，簡單的詞（`日常`、`工作`、`部署`、`追劇`）。

## 4. 隱私檢查

心情文會公開，寫完檢查一遍：

- 朋友、同事、家人的**真名** → 問使用者要不要保留，或改成「朋友」「同事 A」。
- 地址、公司名稱、學校、電話、車牌、帳號 → 拿掉或泛化。
- 技術相關的 IP、token、密碼 → 換成占位字（`x.x.x.x`、`<TOKEN>`）。

## 5. 給使用者確認（一定要）

心情是很個人的東西，送出前**一定**先讓使用者看過：

1. 在對話裡貼出：標題、摘要、潤飾後全文。
2. 用 AskUserQuestion 問一題，選項：
   - 「送出成草稿」
   - 「我要改一下」（使用者說要改哪裡，你改完再給使用者看一次）
   - 「口吻再更像我一點」（改得更保守、更貼近原文，再給使用者看一次）

沒有得到「送出」之前，不要執行送出。

## 6. 送出

1. 寫到 scratchpad（沒有就用系統暫存資料夾）的 `mood-<日期>.md`：

   ```markdown
   ---
   kind: mood
   title: 標題
   excerpt: 一句摘要
   tags: [日常]
   ---

   （潤飾後的內文，不要放 # 大標題）
   ```

2. 跑 `node ~/.claude/skills/tech-note/send.mjs <檔案>`（跟 /tech-note 共用同一支腳本和設定檔 `~/.claude/tech-note.json`）。
   - 出現「缺少設定」、401、503：照 /tech-note 的說明處理，**不要**叫使用者把 token 貼到對話裡。

## 7. 回報

一兩句：標題、編輯連結（腳本印出的 `編輯／發布` 網址）。提醒是**草稿**，到後台按發布才會公開。
