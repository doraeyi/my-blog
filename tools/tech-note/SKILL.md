# /tech-note：對話 → 技術文章草稿

把**目前這段對話**裡真實發生過的卡關與解法，寫成一篇能直接發在部落格上的技術文章草稿，然後送到部落格存成**草稿**（不會自動發布）。

## 1. 選主題

- 有給參數（`/tech-note Cloudflare 525`）：只寫跟那個主題有關的部分。
- 沒給參數：從對話裡找出「有卡住、有解掉」的段落。只有一個就直接寫；有好幾個就列出來（每個一句話），用 AskUserQuestion 問要寫哪個（可多選，每個主題一篇）。
- 對話裡沒有真的卡關或解法（只是聊天、只改小東西）就直說，不要硬寫。

## 2. 寫文章

用**繁體中文**、第一人稱（「我」）、口吻像工程師寫給同行看的開發筆記：直接、具體、不灌水。

結構（標題可依內容調整，沒有內容的段落就拿掉）：

```markdown
## 背景

在做什麼、環境是什麼（框架／版本／部署方式），一兩段就好。

## 卡住的地方

症狀是什麼。真實的錯誤訊息、指令輸出放進 code block（去敏後）。

## 試過的方法

依序列出試過但沒用的方向，以及為什麼沒用。這段是最有價值的部分，不要省略。

## 最後的解法

實際有效的做法：關鍵程式碼、設定、指令。只放必要片段，不要貼整個檔案。

## 為什麼這樣可以

背後的原因／原理。

## 學到的事

2～4 點條列，下次遇到能直接用的經驗。
```

規則：

- **只寫對話裡真的發生過的事**。沒驗證過的推測要標明「我猜」或乾脆不寫；不要捏造錯誤訊息、數字或結果。
- 程式碼片段要跟最後實際採用的版本一致。
- 標題要具體、讓人搜得到（例如「Cloudflare 525：Tunnel 掛掉之後改用 A 記錄直連 Traefik」），不要「解決了一個問題」這種。
- `excerpt` 一到兩句，講問題跟結論。
- `tags` 3～6 個小寫英文或常見中文技術詞（`sveltekit`、`docker`、`cloudflare`、`three.js`）。
- 同一系列的文章可以填 `series`。

## 3. 去敏（送出前一定要做）

寫完後逐項檢查，換成占位字：

| 類型                                                   | 換成                        |
| ------------------------------------------------------ | --------------------------- |
| 任何 token、API key、密碼、secret、cookie、`.env` 的值 | `<TOKEN>`、`<API_KEY>` 之類 |
| 公網／內網 IP                                          | `x.x.x.x`                   |
| SSH 主機、帳號、port、跳板、內部主機名                 | `<server>`、`<user>`        |
| Email、真實姓名以外的帳號名稱                          | `<email>`、`<account>`      |
| 本機路徑裡的使用者名稱（`C:\Users\xxx`、`/home/xxx`）  | `<user>`                    |
| 私有 repo 名稱、內部網址、資料庫內容、別人的個資       | 拿掉或泛化                  |

公開資訊（部落格網域、開源套件名稱、官方文件連結）可以保留。伺服器端還會再掃一次，但**不能依賴它**。

## 4. 存檔並送出

1. 把草稿寫到 scratchpad（沒有 scratchpad 就用系統暫存資料夾），檔名 `tech-note-<slug或日期>.md`，格式：

   ```markdown
   ---
   title: 標題
   excerpt: 一兩句摘要
   tags: [tag1, tag2]
   series: 系列名（可省略）
   ---

   （內文，從「## 背景」開始，不要再放 # 大標題）
   ```

2. 先跑 `node ~/.claude/skills/tech-note/send.mjs <檔案> --dry-run` 確認 front matter 解析正確。
3. 再跑 `node ~/.claude/skills/tech-note/send.mjs <檔案>` 送出。
   - 出現「缺少設定」：請使用者在 `~/.claude/tech-note.json` 放 `{ "url": "https://blog.doraeyi.com", "token": "…" }`，token 要跟伺服器 `.env` 的 `TECH_NOTE_TOKEN` 一樣。**不要**在對話裡要使用者貼 token。
   - 401：token 不一致；503：伺服器還沒設定 `TECH_NOTE_TOKEN`。

## 5. 回報

用兩三行告訴使用者：文章標題、編輯連結（send.mjs 印出的 `編輯／發布` 網址）、伺服器額外遮掉了什麼。提醒它還是**草稿**，要到後台看過再發布。
